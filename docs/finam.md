# Шлюз Finam Trade API

Как коннектор читает MOEX через Finam и что о шлюзе известно. Каждое
утверждение — с источником: контракт `.proto`, замер в репозитории
bdpb-research-lab (коллектор `internal/collector/moex`, `docs/collector.md`,
раздел «Второй шлюз»; дальше — «лаборатория»), проверка этого репозитория.

## Доступ

- Хост `api.finam.ru:443`, gRPC поверх TLS. Сертификат проверяется по
  системному хранилищу JRE; отдельного корня, как у T-Invest, не нужно.
- Нужен секрет из раздела «Токены» портала Finam Trade API (брокерский или
  демо-счёт). Квал-статус для данных не требуется.
- Лимит — 200 запросов в минуту на метод (`.proto`). Отказ по лимиту
  (`RESOURCE_EXHAUSTED`) коннектор пережидает минуту.

## Авторизация

| Шаг | Вызов | Подробности |
|---|---|---|
| Секрет → JWT | `AuthService/Auth` | JWT живёт 15 минут; коннектор обновляет его по возрасту 10 минут и сразу после `UNAUTHENTICATED` |
| JWT в запросах | заголовок `authorization` | голая строка JWT, без `Bearer` (примеры Finam; проверено в лаборатории 12.09.2026) |
| Сведения о токене | `AuthService/TokenDetails` | **без** заголовка, токен в теле: с заголовком шлюз отвечает «Token is invalid or malformed» (лаборатория, 12.09.2026). Отдаёт счета и права на данные |

Неверный секрет шлюз встречает `UNAUTHENTICATED — Api token could not be verified`
(проверено этим репозиторием 08.11.2026), и Bookmap получает `WRONG_CREDENTIALS`.

## Справочник

- `AssetsService/GetAsset(symbol, account_id)` — шаг цены
  (`min_step / 10^decimals`), лот, тип, наименование.
- **Счёт обязателен**, хотя в контракте поле необязательное: без него —
  400 «Invalid arguments: account_id» (лаборатория, 12.09.2026). Коннектор берёт
  первый счёт из `TokenDetails` или счёт из окна входа.
- Символы — `ticker@mic`: `RTSX` — срочный рынок, `MISX` — фондовый. Как
  коннектор строит символ из ввода пользователя — README, раздел «Подписка».

## Стримы

На инструмент — два server-side стрима; шлюз принимает один инструмент на стрим.

| Стрим | Что приходит | Как обрабатывается |
|---|---|---|
| `SubscribeOrderBook` | сообщение с `is_data_snapshot` — полный снимок (все строки `ACTION_ADD`, порядок не биржевой); остальные — построчные `ADD` / `UPDATE` / `REMOVE`, сторона — заполненное `buy_size` или `sell_size` | снимок сравнивается с текущим стаканом, разница уходит в Bookmap; изменения применяются по одному |
| `SubscribeLatestTrades` | сначала последние сделки с `is_data_snapshot`, затем живые; `side` — сторона агрессора | история пропускается, живые сделки уходят в Bookmap |

Снимок стакана приходит при подписке, после переподключения и раз в 60 секунд
(лаборатория, 12.09.2026: 11:07:09, 11:08:09, …). Каждый такой снимок
выравнивает стакан, поэтому пропущенное изменение живёт не дольше минуты.

Служебного heartbeat в стримах нет; живость соединения проверяют ping-кадры
HTTP/2 раз в 30 секунд с ответом за 15. Шлюз рвёт стримы в техокно
05:00–06:15 МСК и раз в сутки; коннектор переоткрывает их с паузой от 1 до 30
секунд.

## Права на данные

Глубина стакана не документирована и зависит от прав токена
(`MDPermission.quote_level`). Коннектор пишет права в журнал Bookmap при входе:

```text
[MOEX] Finam: вход выполнен; счёт для справочника: 1440399; права на данные: RTSX: DEPTH_OF_MARKET; MISX: DEPTH_OF_MARKET
```

`DEPTH_OF_MARKET` — агрегированный стакан, `DEPTH_OF_BOOK` — полный. У ключа
лаборатории на 12.09.2026 был `DEPTH_OF_MARKET` без задержки по `RTSX`; BTU6
отдал 54 строки.

## Что не проверено живьём

Проверять в будний день, в торговую сессию:

- [ ] как выглядят изменения стакана на торгующемся рынке: в записях
      лаборатории 12.09 (суббота) были только снимки;
- [ ] указывает ли строка `REMOVE` сторону — коннектор умеет и без неё;
- [ ] в каких единицах объём акций — лоты или штуки;
- [ ] реальная глубина стакана по правам токена на `MISX`;
- [ ] переподключение через техокно и после суточного разрыва;
- [ ] обновление JWT через 10 минут работы.

## Контракт

`.proto` лежат в `src/main/proto` без изменений, из
[FinamWeb/finam-trade-api](https://github.com/FinamWeb/finam-trade-api),
коммит `fef964d` (27.10.2026), лицензия Apache 2.0 (их Kotlin SDK). Взяты
только нужные файлы: `auth`, `assets`, `marketdata`, `side` и аннотации
OpenAPI, которые они импортируют. `google/api` и `google/type` приходят из
`proto-google-common-protos`.

Обновление: заменить файлы из свежего клона по тем же путям, выполнить
`./gradlew build` и поправить здесь коммит и дату.
